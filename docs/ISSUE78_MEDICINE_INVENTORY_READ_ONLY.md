## Schema and authorization

| Table | Purpose | Authenticated API |
| --- | --- | --- |
| `medicine_catalog` | Shared medicine ID, unique product code, generic label, formulation, strength, indivisible stock unit, minimum shelf-life days, refrigeration/controlled classification and active flag | SELECT of non-sensitive columns **only for staff with at least one live active authorized branch/global role**. No public/anon or writes |
| `branch_medicine_rules` | Per-branch+medicine unique reorder point and configurable **30/60/90** days | SELECT by **current active branch membership**; no writes |
| `branch_stock_batches` | Per-branch+medicine lot, received/expiry dates, disposition, integer on-hand/reserved/quarantined, optional supplier reference, optional unit cost in minor currency units | Only current staff of the same branch can SELECT non-cost fields; `unit_cost_minor` and `currency_code` deliberately have **no authenticated column SELECT grant**. No writes |
| `stock_movements` | Per-branch+medicine+batch append-only immutable ledger with explicit deltas and after-balances, correlation event, reason code, actor and timestamp | Same-branch staff SELECT only. No INSERT/UPDATE/DELETE/TRUNCATE. Privileged UPDATE/DELETE/TRUNCATE also blocked with audit trigger |

All four new `public` tables have RLS enabled. Policies reference `clinic_private.has_branch_role(branch_id,roles)` from the exact PR80 branch foundation; this checks current provider `auth.users` state, email confirmation, bans, active global `staff_memberships` role **matching** the active `staff_branch_memberships` role. Neither user-supplied `branch_id`, the `active_branch_id` JWT claim, nor public clinic hours conveys authorization. Column grants and RLS both fail closed. Owners, anonymous/unconfirmed accounts and globally/branch-revoked staff cannot read a catalog or branch inventory. The catalog remains shared *only across currently authorized staff*; it never contains patient medication data.

Quantities are **integer units of the declared catalog `stock_unit`**; no floating conversion or implicit package/vial/tablet conversion is allowed. SQL CHECK constraints enforce `on_hand>=0`, `reserved>=0`, `quarantined>=0`, `reserved+quarantined<=on_hand`; expiry cannot predate receipt. Compound batch FK on the ledger prevents recording a Cavite movement against a Naga batch. Batch identity/lot uniqueness is by branch+medicine+lot+expiry; duplicate event IDs are rejected per branch.

## Safe read-only SQL API (all `SECURITY INVOKER`, explicit authenticated EXECUTE only)

- `public.list_branch_medicine_fefo(p_branch uuid,p_medicine uuid)` first calls existing `public.assert_staff_branch`, then returns only **active-catalog**, same-branch batches with `disposition='released'`, remaining shelf life beyond **today + configured minimum days** and `on_hand-reserved-quarantined>0`. Stable **expiry ascending, received ascending, lot ascending, batch UUID ascending**; includes lot ID and currently eligible integer units, **not** an executable dispensing instruction. Expired, quarantined, recalled, zero-available and short-shelf-life batches cannot be returned as candidates.
- `public.list_branch_medicine_alerts(p_branch uuid)` asserts the live branch and returns one row per configured branch medicine: summed **available** unexpired/released units, reorder point, `out_of_stock` at zero, `low_stock` at `available<=reorder_point`, **near-expiry** batch count for the configured 30/60/90-day inclusive horizon, and **separate** expired and quarantined/recalled counts. These are informational SELECTs evaluated at query time, not approved treatments, automatic procurement or dispatched notifications. An unconfigured medicine generates **no** alert row; zero alerts do not prove full catalog inventory coverage. The windows use PostgreSQL `current_date` (database timezone), not per-branch published hours. Philippine-local date reconciliation requires deployment governance before activation.

Every read is additionally filtered by table RLS. Staff assigned to both branches may read each explicitly; branch context is never implicitly inherited from a previously selected branch. Only real, approved branch staff should receive access after the separate provider rollout approval.

## Mutation contract — EXPLICITLY DISABLED (no partially secured dispense)

**Mandatory next backend phase before enabling a single write**: explicit approved catalog/branch inventory roles, stock reconciliation and base ledger import, clinical encounter/prescription linkage and consent as appropriate, `SELECT ... FOR UPDATE` locks on **all affected batch balances in deterministic order**, exact idempotency keys, frozen unit conversions, nonnegative postconditions, same-transaction batch and append-only ledger commit, durable audit actor+reason and action approvals, isolation-level/race/retry tests in separate real PostgreSQL sessions. **Transfers** require both sender and receiving branch authorization/acknowledgement, in-transit state, two-sided matched ledger records and atomic reconciliation; never merely subtract A/add B. No auto-write RPC, scheduler, alert messages, delivery or purchase is exposed until separately signed off.

## Proposed CLOUD integration contract
POST authenticated Supabase RPC `reconcile_staff_clinical_draft(p_branch uuid,p_pet uuid,p_appointment uuid,p_request_id uuid|null,p_before_revision integer|null)`. The last two arguments default to null. Both cannot be supplied simultaneously. Current active veterinarian only; exact patient/owner/appointment/branch; own receipts only. Admin stays read-only via existing chart API, no receipt discovery. Never call with service role. Reauthenticate, check account and selection before dispatch; abort/ignore late results after account/branch/visit change. Do not persist note text, response, or patient/visit IDs in browser storage. Request UUID can remain in memory; after reload reopen the authorized visit and discover receipts without any stored ticket.

Reply includes `accountId,branchId,petId,appointmentId,requestId,beforeRevision,kind,currentRevision,draftId,receipt`. Echoed requestId/beforeRevision can be null. Validate every context field and shape, and treat mismatch/unavailable/denied as unresolved, never success. 
* committed: receipt {requestId, revision, auditEventId (decimal string), savedAt (timestamp string)}. CurrentRevision >= receipt.revision; draftId identifies current encounter. Exact lookup proves only that UUID committed. Discovery (null nonce) returns newest own receipt; call again with p_before_revision=receipt.revision for earlier own revisions; not_found ends the page sequence. Discovery is evidence of prior accepted saves, not proof that a lost unidentified request was committed. Never automatically label it the uncertain save. Read current chart separately; validate appointment and draftId, revision; if advanced, show newer chart and distinguish saved revision from current. No raw medical payload returned.
* not_found: no matching receipt visible in this authorized visit at observation time; currentRevision 0 means no draft. NOT proof that a delayed or not-yet-dispatched original request will never commit. No automatic mutation replay, new UUID, or rebase. Show authoritative chart and require explicit clinician decision after unresolved state is explained; keep prior unsaved content only in memory if present.
* unknown: visit_busy or receipt_unverified, receipt/currentRevision/draftId null. Network failures, unavailable RPC, invalid response, expired session and permissions are likewise not confirmation. Retry only the receipt lookup/readback, never the save. No indefinite background polling.
* 42501 denied; 22023 invalid inputs. Existing save conflict codes remain unchanged. No frontend flags activated.

The lookup uses the existing visit advisory transaction lock non-blockingly, requires current live session (#18), and locks role/Auth/appointment/patient rows for authorization; no medical table mutation. A new session for the same actor can discover committed receipts. A different account cannot see them. The journals remain private and immutable. Existing #17 save and read APIs are unchanged; their session-policy scope is separate from this new RPC, and must be independently assessed before hosted activation. This endpoint does not claim to recover text that never committed.

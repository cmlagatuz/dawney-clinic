## Why the network sender is deliberately absent

The reviewed acceptance runner validates a signed short-lived owner approval, checks source hashes, and opens an exclusive durable cleanup journal BEFORE it calls the injected transport. An independently callable network adapter could bypass this journal and replay the owner-approved synthetic writes without preserving their cleanup metadata. This PR deliberately ships only a **pure in-memory request planner** at scripts/hosted-acceptance/staging-request-plan.mjs. It has NO fetch, HTTP/socket/SDK import, sender, network callback, or direct runnable transport. Direct CLI exits 3. The original acceptance.mjs CLI remains inert and exits 3.

The planner takes a preexisting runner request and refuses any plan unless:
- The unchanged verifyOwnerGate succeeds with an RSA-signed approval and an independently pinned owner signing-key SPKI fingerprint, approved original backend SHA, signed Grok-reviewed harness file SHA-256s, explicit synthetic-write consent, run ID, and at most 60-minute time window.
- The owner-signed claims additionally contain **stagingPlanSha256** matching the bytes of this exact added module. The original reviewed guards and acceptance code are not changed; older signatures without this extra claim fail closed. Operator must separately pin the reviewed delivered Git commit, because self-checks alone do not establish a trusted binary.
- The exact staging reference is **gxklkkoffpkdcxbqjlav**, and the only origin is **https://gxklkkoffpkdcxbqjlav.supabase.co**. Protected production ref **lgimhirgvresvbsdugac** is denied. Other signed staging projects, ports, arbitrary hosts and URL normalization or encoded-path tricks are refused.
- Only reviewed Auth/JWKS, scoped owners/pets/appointments/staff reads, request-service-appointment synthetic booking POST, negative owner PATCH, private clinical attachment PDF/negative .exe upload, and authenticated/public Storage GET are representable. Other methods, SQL, signup, bucket admin, delete, arbitrary REST/queries, privileged headers, service keys and non-synthetic payloads fail closed.
- Output declares redirectPolicy=error and credentialsPolicy=omit. The validated JSON and PDF body is privately captured as exact UTF-8 or binary bytes, SHA-256 bound to an immutable descriptor; each `plan.body` read is a fresh defensive copy. A future journal-bound sender must call `materializeValidatedStagingBody(plan)` at the outbound consumption boundary and reject any unrecognized/fabricated descriptor; it must never cache and later trust an editable copy. The exported planner rejects caller-supplied `now` and asks the existing owner gate to evaluate against its own `Date.now()`. The original guard's injectable clock is unchanged for its own isolated testing. It is a **request description**, never a request execution. Response parsing and real JWT validation remain the later runner/transport responsibility.

The .exe path is deliberately representable for a **denial** test, not authorization to accept it; any successful .exe upload during later hosted verification is a hard NO-GO. Staff revocation, nonce replay, cross-owner access and Storage binary comparisons are still asserted by the unchanged reviewed harness.

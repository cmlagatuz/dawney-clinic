# Phase 4 security audit (Grok) — issues #37 and #35

Scope: `supabase/migrations/20261113211600_phase4_taxonomy_attachments.sql`, `supabase/migrations/20261113211700_phase4_animal_catalog_seed.sql`, and storage policies in `supabase/migrations/20261113100958_phase3_clinical_storage_policies.sql`. Master SHA `f37a884`. No production migration, no patient writes, Astra SQL and Claude UI not modified.

| Sev | Finding | Evidence | Astra action |
|---|---|---|---|
| High | Taxonomy enforcement function is never installed as a trigger. `is_active` / `review_status <> 'pending'` checks live only in `clinic_private.resolve_pet_taxonomy()`. Do not edit the already-authored Phase 4 file if it may have been copied locally. |

Optional later: scheduled orphan report. Not a substitute for the High fixes. |

What holds: catalogs have RLS, SELECT-only grants, no user INSERT/UPDATE/DELETE policies. Attachment table has no UPDATE/DELETE grant or policy. `uploaded_by` must equal `auth.uid()`. Owner path and clinic path are split; clinic insert is veterinarian or administrator. `version_no` is not client-grantable and is assigned under `pg_advisory_xact_lock`. `ON DELETE RESTRICT` on attachment `pet_id`. Anon has no grants.

Role notes: pet owner can read/insert only own pet owner-prefix. Veterinarian and administrator can insert clinic-prefix for any existing pet (single-clinic model). Receptionist cannot insert attachments. Administrator is not broader than veterinarian on this surface.

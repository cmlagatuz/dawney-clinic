# Phase 3 — React/TypeScript/Vite frontend foundation

**Branch:** `ai/chatgpt/phase3-web-foundation`. Source reference remains the legacy Laravel app, which this work does not modify.

## Scope

A standalone `web/` application builds to static `dist/` for Cloudflare Pages Free. This initial milestone covers Supabase Auth (email/password sign-in, verification links/OTP, signup, resend, recovery, secure local browser session persistence through official Supabase JS, sign-out), protected routing, accessibility and responsive desktop/mobile layout, owner profile create/edit/read in PostgreSQL through RLS. `Patients` and `Appointments` are visibly labeled **not yet connected** until their separate clinical milestone. No mock rows masquerade as live data.

- Official `@supabase/supabase-js` stores renewable session tokens in browser storage by default. `persistSession:true`, PKCE redirects, automatic token refresh and `getUser()` server verification are configured. Security boundary is database RLS: frontend route guards only manage display. Stored tokens require robust XSS prevention and CSP; do not put any third-party scripts or user-generated HTML into this app.
- `owners` INSERT does not submit `user_id`, trusting DB default `auth.uid()` and RLS. `owners` UPDATE uses only allowed columns and filters by authenticated UUID; sensitive PK/user ownership columns cannot be modified in browser.
- Verified email is a mandatory gate, and Auth user metadata is used only to prefill a name, never as an authorization role.
- Staff role assignment remains operator-only (Phase 2 private DB functions), not a frontend button.
- Error/loading/status messages use accessible labels and roles. No paid services, SMS or vendor integrations.

## Local setup

```bash
cd web
npm ci
cp .env.example .env.local
# In .env.local fill VITE_SUPABASE_PUBLISHABLE_KEY with the public key only.
npm test
npm run build
npm run dev
```

The committed `web/package-lock.json` is generated by a GitHub Actions bootstrap job on the isolated Phase 3 branch from pinned direct dependencies, then all PR/master builds use `npm ci`. Never add service-role, SQL passwords or signing keys to `VITE_` variables.

## Supabase Auth redirect URL setup

After choosing a local development URL or final Pages preview domain, open Supabase **Authentication > URL Configuration**. Add the exact permitted URLs, e.g. `http://localhost:5173/auth/callback`, `http://localhost:5173/auth/recovery`, and corresponding HTTPS URLs for the approved `*.pages.dev` site. The live project must not accept arbitrary redirect URLs. Supabase confirmation links will redirect to the app, and `createClient({auth:{flowType:'pkce',detectSessionInUrl:true}})` handles the code exchange. Email reset links use `/auth/recovery`.

### Rollback

From Cloudflare Pages deployment history, select the last verified production deployment and use **Rollback to this deployment**. Since static builds do not rewind Supabase database, protect migrations separately with backup + tested restore; do not roll back schema blindly. Disable patient onboarding during an incident, restore verified data in an isolated database and obtain owner approval before cutover.
